# So-VITS-SVC 多用户推理服务器

独立部署的 so-vits-svc **推理 Web 服务**，支持多用户注册、模型审核、资源配额、
公平调度、服务器统一邮件通知。用户上传音频后异步推理，完成后下载结果。

## 功能

- **多用户注册**：开放注册（可在后台关闭），注册后自动登录、带默认配额
- **模型管理**：用户上传私有模型，需**管理员审核**通过后才能推理；管理员可发布**官方共享模型**并上/下架
- **资源配额**：管理员为每个用户配置排队/运行任务数、单音频时长、每日音频秒数、私有模型数、结果保留天数
- **公平调度**：推理任务按用户公平轮转 + 优先级排队，单 GPU 串行执行，执行器失联自动回收
- **服务器统一邮件**：管理员配置一次 SMTP，用户可设置**结果接收邮箱**，推理完成后收到含下载链接的邮件
- **结果对象级下载**：结果按任务归属鉴权下载，默认保留 7 天后自动清理（可在后台配置）
- **推理性能**：常驻 daemon + LRU 模型缓存（同模型连续推理零加载开销）、ONNX 加速、失败自动回退 PyTorch
- **管理员后台**：总览、用户配额、全局任务队列、模型审核/官方管理、存储与孤儿文件、站点设置、SMTP 设置
- **安全**：CSRF、登录/注册限速、路径穿越防护、会话密钥持久化、模型可用性校验

## 模型架构

| 架构 | 结构 | 特点 |
|------|------|------|
| `sovits-v1` | TextEncoder + Flow + enc_q（原版 VITS） | 兼容性最好，与社区模型互通 |
| `rvc` | 特征直连解码器 | 训练更稳更快，适合小数据 |
| `rvc-flow` | 轻量 TransformerFlow（A1/A2） | 音质上限更高，A2 可开统一流 |

- **A1 特征先验流**：`z` 由源音频内容特征决定，解耦音色与发音
- **A2 后验流**（默认）：极小 enc_q 提供后验，训练更稳
- **统一流**：A2 可开启，同一骨干同时承载 NF 与 FM，推理可选 `nf / fm / hybrid` 三模式（详见 [docs/unified_flow.md](docs/unified_flow.md)）

## 快速开始

### Windows

```bat
install.bat      :: 建 venv + 装依赖
start.bat        :: 启动服务，访问 http://localhost:5000
```

### Linux 部署

```bash
sudo bash deploy_linux.sh   # NVIDIA GPU / AMD ROCm / CPU 自动适配
```

首次启动会在控制台打印管理员初始密码（`admin` 账号），登录后强制修改。

## 配置

| 环境变量 | 作用 | 默认 |
|---------|------|------|
| `PORT` | 服务端口 | 5000 |
| `SECRET_KEY` | 会话密钥（自动持久化） | 自动生成 |
| `DATABASE_URL` | 数据库路径 | server/data.db |
| `INFERENCE_TASK_TIMEOUT` | 单任务推理超时（秒） | 21600 |
| `INFERENCE_MODEL_CACHE` | 推理模型缓存数量 | 3 |
| `ALLOW_REGISTRATION` | 是否开放注册 | 1 |
| `SMTP_HOST/SMTP_PORT/SMTP_USER/SMTP_PASS/MAIL_FROM` | 服务器 SMTP（也可在后台配置） | 空 |
| `SSVC_SERVER_URL` | 邮件内下载链接的访问地址 | 自动探测 |

## 使用流程

**用户**
1. 注册账号（填写邮箱与结果接收邮箱）
2. 模型页上传私有模型 → 等待管理员审核
3. 审核通过后创建推理配置（可选用官方共享模型）
4. 推理页选配置 + 上传音频 → 提交（自动进入公平队列）
5. 任务列表查看进度、下载结果；结果保留到期后自动清理

**管理员**（后台“管理”入口）
- **总览**：用户数、排队/运行任务、今日完成/失败、磁盘占用
- **用户**：启用/禁用账号，调整每个用户的资源配额
- **模型**：审核私有模型（通过/拒绝）、官方模型上/下架、私有转官方
- **任务**：查看全局任务队列，停止/删除异常任务
- **存储**：磁盘占用统计，删除无归属的孤儿文件
- **设置**：注册开关、新用户默认配额、结果保留天数、SMTP 配置

## 常见问题

**上传的模型为什么不能立刻推理？**
私有模型需要管理员在后台“模型”页审核通过后才能使用；也可直接使用平台发布的官方模型。

**推理完成后怎么收到结果？**
设置页填写“结果接收邮箱”，并开启“推理完成时发送邮件通知”；服务器 SMTP 需由管理员配置。

**任务一直排队 / 进度不动？**
模型加载阶段（CPU 上 1~2 分钟）无进度是正常的；单 GPU 按用户轮转，长任务会让后续任务排队。

**服务器内存小（OOM）？**
调低 `INFERENCE_MODEL_CACHE=1`，推理配置 `cluster_ratio=0`，限制单音频时长与每日额度。

## 注意事项

- 模型权重、数据库、密钥、上传文件等**不进入 git 仓库**
- CPU 可推理但较慢；F0 预测器建议 `pm/harvest`（`crepe` 慢数倍）
- 管理员后台所有操作仅 `admin` 角色可见，普通用户访问返回 403
